Certrace Portal 8 · Design system, as built

What the portal
is using today.

Every value on this page was read from the running portal's code — app/globals.css, components/ui.tsx, components/controls.tsx, the shell and the workspace chrome — not from the earlier brand pack. Where the portal's remaps change a size or a grey, the rendered value (what a user sees) is shown.

Light mode only. The portal is ink-on-bone with no dark theme. The single dark hook is the Cera mark's [data-theme="dark"] block. Colour is used for status only; the one non-status accent is blue #3C7ACB on the English-only notice.
Generated 26 Oct 2026 from certrace-portal8/certrace-portal. The 8 July Brand Book & Design System pack is superseded for anything that differs from this page — notably the larger type scale, the stronger greys, the Geist body face and the four-language type stack.
01 · Foundations

Principles.

The rules the code itself states, in the order it states them.

Ink on bone

A #F5F4F0 canvas, white cards, #111 for every primary action. Nothing is coloured unless it is saying something about status.

Borders, not shadows

Cards and fields are a 1px hairline of black at 7–10%. Shadow is reserved for things that float: popovers, toasts, modals.

Hierarchy by opacity

Text is black at a ladder of opacities (see Colour). Display type is IBM Plex Sans at weight 300; everything else is Geist.

Readable first

Nothing is set below 12px, body is 15–16px, and no secondary grey falls under WCAG AA. The portal's readers are mostly over fifty and often read Thai.

One primitive, one place

Buttons, links styled as buttons, chips, fields, popovers, modals: each class string lives in exactly one component, so two screens cannot drift.

Confirm where it was pressed

A button says what it just did (Saved ✓) instead of raising a toast the reader has to look away to find.

07 · Components

Buttons.

components/ui.tsx · Button, ButtonLink, SaveButton, useSaveState, useFlash

All buttons are uppercase, tracking-[0.1em], rounded-xl, with a dark fill for the single primary action. ButtonLink is the same control rendered as an anchor — a destination is a link, never a button + router.push. Disabled is opacity-40 with no pointer events.

Variants · md (px-6 py-3, 15px)
sm (px-4 py-2, 13px)
SaveButton · idle → saving → saved (click)
Always size="sm". The spinner is light on primary, dark on secondary/ghost.
Confirm in place. After an action, swap the label and colour for ~2.2s (useFlash) with a tick that pops in (ct-confirm, 0.26s). A control that leaps on success reads as one that broke, so the motion is deliberately small.

Form controls.

components/ui.tsx · Field, inputClass, NumberInput, Checkbox, Switch · components/controls.tsx · Select, MultiSelect, Dropdown, Calendar, DatePicker, SelectWithOther, OrderedMultiSelect

Native <select> and <input type=date> are never used, so the control looks identical on Windows, macOS, iOS and Android. A select is the same height and padding as a text field (px-4 py-3) — a select six pixels shorter than its neighbour is the clearest sign a form is unfinished.

Field & input

inputClass = w-full rounded-xl border border-black/10 bg-white px-4 py-3 text-sm text-black/70 placeholder:text-black/25 focus:border-black/25 focus:outline-none, plus a shared disabled state (cursor-not-allowed, border black/7, bg black/2, text black/40) so a locked form looks locked everywhere.

Feedback & overlays.

components/toast.tsx · ui.tsx · AutoSaveBadge, EmptyState, EnglishOnlyNotice, Modal

Toast

Supplier link copied

Valid for 14 days.

Bottom-right (centred on phones, w-[calc(100%-2rem)] max-w-sm), z-100, auto-dismiss after 4.2s, enters with ct-enter. Fired by a plain function call toast(msg | {message, tone, detail}); the message is translated when shown. Prefer confirm-in-place for the button's own result.

Auto-save badge

All changes saved Unsaved changes… Saving… Saved automatically at 14:32 Could not save — copy your entries before leaving

Every verification field writes on its own (600ms debounce, compared by content so an inline object cannot loop it) and says so: auto-save without a visible state is indistinguishable from auto-save that is broken. 13px, aria-live="polite".

Empty state

No suppliers yet

Add the sites that make your goods and send each a link to fill in their part.

English-only notice

Please write everything you type in English — an EU-accredited verifier reads it. Numbers and dates stay as they are.

Stated where the typing happens, once per screen. The regulatory reason (2025/2547 Art. 5(6), 10(4)) sits behind the "?" so the strip stays one line. Numbers are not text — the copy says so to avoid implying a bigger ask than it is.

Modal

Portaled, z-300, scroll-locks the page, Esc closes. Bounded by the viewport, not a fraction of it: max-h: calc(100dvh − 2rem) (−3rem ≥sm) laid out as a column — header and footer flex-none and always visible, only the body scrolls (min-h-0 flex-1 overflow-y-auto overscroll-contain). dvh, not vh, because mobile Safari's vh includes the collapsing address bar. 13 · Behaviour

Motion.

app/globals.css · keyframes ct-*

Signature easing cubic-bezier(0.16, 1, 0.3, 1). Motion is an entrance or a response, never decoration. Click a card to replay.

ct-enter
0.7s blur-in + 14px rise. A page section arriving. Never on a menu.
ct-pop
120ms, −4px, no blur. Menus, dropdowns, calendars, help tips.
ct-row
0.4s, 8px rise. List rows.
ct-focus
2.6s green ring that settles — where a link just brought you.
ct-confirm
0.26s scale .7→1.1→1. The tick on a button.
ct-sweep · ct-pulse
Indeterminate: "in hand", not "37% done".
Why ct-pop exists. A blur filter smears outside its own rounded box and clip: on a dropdown, the selected row ghosted above the panel for most of 700ms, as if the trigger had been drawn twice. A menu is a response to a click, not an arrival.
Reduced motion: prefers-reduced-motion collapses every animation and transition to 0.01ms and disables smooth scroll; ct-focus falls back to a static 3px green ring.
