## Decision Log

<!-- Significant technical decisions with rationale. Why X was chosen over Y. -->

- [2026-11-11] CBAM answers live at workbook cell `cbam:0:<field id>` (field id = `<sheet letter>-<template cell>`, e.g. `a-i20`). Fill in and the per-item Smart Link (`/s/item/[token]`) write the same cells. The backend reads its field list from `certrace-backend/src/modules/links/cbam-item-fields.json`, generated by `certrace-portal/scripts/write-item-fields.ts`; rerun it after changing `lib/cbam/template-fields.ts`.
- [2026-11-11] bun 1.3.14: `await expect(promise).rejects` hung on a rejection thrown by `fail()` in item-links tests. Use try/catch and assert the code.
- 2026-11-11: Workspace CBAM tab must be passed to both Spreadsheet renders in app/(portal)/workspace/page.tsx (the not-started-year preview too), because Fill in / Smart Link write cbam:0:* cells before a year is started.
- 2026-11-11: In `next dev` (Next 15.5.28, bun node_modules), every `runtime = "edge"` page returns 500 with "Could not find the module ... in the React Server Consumer Manifest", including the existing /s/[token]. Cause: Windows backslash ids vs a forward-slash-only regex in Next's flight-client-entry-plugin. Fixed by `patches/next@15.5.28.patch` (bun patchedDependencies in root package.json). On a Next upgrade, re-check and re-create or drop the patch.
- 2026-11-12: Cera actions use BARE CBAM field ids (`a-i9`); the backend allowlist comes from cbam-item-fields.json, and the portal adds `cbam:0:` only when patching cells. The server never writes. The portal ActionCard runs `applyCeraAction` only on Confirm. update_installation writes the installation store, which flushAccount syncs to server records (certrace:installations).
- 2026-11-12: Cera picks a provider in src/modules/cera/provider.ts. Groq free tier (GROQ_API_KEY, gpt-oss-120b falling back to 20b on 429) works for tool calls. With no provider key, Cera answers in rules mode and action cards never appear.
- 2026-11-12: Any change to the portal Installation type (or another stored account record) needs `bun scripts/generate-report-storage.ts` in certrace-backend, then a backend restart. validateStore rejects unknown fields, so a stale catalogue.ts fails the whole record save with "unrecognized field".
- 2026-11-12: lib/i18n.ts loads th/zh/hi dictionaries lazily (loadLocale). The UI renders English until the chunk arrives. Tests preload all locales in scripts/test-resolver.mjs, so synchronous translate() in tests still works.
- 2026-11-12: After editing next.config.ts the running `next dev` can return 500 with the RSC manifest error even with the patch present. Restart the dev server.
- 2026-11-12: Fill in back link uses `?from=<standard id>`. Installation defaults come from `lib/cbam/installation-defaults.ts` and fill only empty cells.
- 2026-11-12: CBAM sheet D repeats per production process every 65 rows (10 blocks, headers D11..D596); sheet E repeats per purchased precursor every 44 rows (20 blocks). template-fields.ts generates them with `blocks()`; blocks 2+ are optional so progress totals are unchanged. UI shows block n only when block n or n-1 has an answer (`visibleBlocks`, used by Fill in, Smart Link and the CBAM tab).
- 2026-11-12: The Cera set_cbam_fields schema lists only block-1 keys plus the stride rule and uses a key pattern, not an enum. The server still checks keys against the full catalogue. Keep it this way so the Groq free-tier TPM budget holds.
- 2026-11-12: Repeated CBAM labels ("Name" in process P1, precursor PP1, verifier) must carry their section in the Cera tool description (`promptLabel` in certrace-backend cera/actions.ts) and on the confirm card (CBAM_LABELS in portal lib/cera/actions.ts). Without it a free model picked a-l102 for "process P1" and the card hid it.
- 2026-11-12: No mock data in portal paths. supplier.ts assembleRequest invents no lots when the link has no product spec; exporter-review has no fake reviewer list; supplier-intake banner states the real PDF reader.
