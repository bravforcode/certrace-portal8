# Shared calculation fixtures

ไฟล์ในโฟลเดอร์นี้เป็น **ของกลาง** ไม่ได้เป็นของฝั่งไหน — ทั้งพอร์ทัลและ backend อ่านไฟล์เดียวกัน
เพื่อพิสูจน์ว่าคำนวณแล้วได้เลขเดียวกันจริง ก่อนจะย้าย source of truth ข้ามฝั่ง

## ทำไมต้องมี

ตอนนี้มีเครื่องคำนวณสองตัวที่ยังไม่เคยถูกเทียบกันเลย:

| | ที่อยู่ | ใช้จริงไหม |
| :-- | :-- | :-- |
| พอร์ทัล | `certrace-portal/lib/cbam/engine.ts` + `precursor-tree.ts` | ✅ ต่อ UI ทุกหน้า |
| Backend | `certrace-backend/app/services/mrv_engine.py` | ❌ ยังไม่มีใครเรียก |

ถ้าวันหนึ่งย้ายไปใช้ backend แล้วเลขขยับ จะไม่มีทางรู้ว่าอันไหนถูก ไฟล์นี้ทำให้รู้

## `golden-eaf-2026.json`

โรงงานเหล็ก EAF ป้อนเศษเหล็ก CN 7213.10 ปี 2026 — ตัวเลขทุกตัวมาจาก spec §5.6

โครงสร้าง:

| ส่วน | คืออะไร |
| :-- | :-- |
| `inputs` | ข้อมูลนำเข้า เขียนแบบไม่ผูกกับ engine ไหน (มีหน่วยกำกับทุกตัว) |
| `expected` | คำตอบที่ถูกต้อง — คือสิ่งที่ทั้งสองฝั่งต้องได้ |
| `tolerance` | 1e-6 สำหรับอัตราส่วน · 1e-4 สำหรับมวล · 0.01 สำหรับเงิน |
| `backend.request` | payload ของ `/api/v1/calculate` ที่แปลงมาจาก `inputs` แล้ว |
| `backend.covered` | บรรทัดที่ backend ทำได้ — เทียบแบบ **ตรงทุกหลัก** ไม่ใช่ในช่วง tolerance |
| `backend.unsupported` | บรรทัดที่ backend ยังทำไม่ได้ พร้อมเหตุผลและวิธีปิดช่องว่าง |

## ใครอ่านไฟล์นี้

```
certrace-portal/lib/cbam/__tests__/parity-fixture.test.ts   ← พอร์ทัลต้องได้ expected ครบทุกบรรทัด
certrace-backend/tests/test_parity_golden.py                ← backend ต้องได้ตรงเป๊ะเฉพาะบรรทัดที่ทำได้
```

เทสต์ฝั่งพอร์ทัลยังเช็คด้วยว่า `lib/cbam/__fixtures__/golden.ts` (ตัว typed ที่เทสต์อื่นใช้)
มีตัวเลขตรงกับ JSON นี้ — แก้ที่เดียวแล้วอีกที่จะฟ้องทันทีถ้าลืมตาม

## กฎการแก้

1. **แก้ `expected` = เปลี่ยนตัวเลขที่จะยื่นจริง** ต้องมีเหตุผลทางกฎหมายกำกับ ไม่ใช่แก้ให้เทสต์ผ่าน
2. **ปิดช่องว่างใน `unsupported` แล้วต้องลบรายการนั้นออก** — เทสต์ฝั่ง backend มี guard
   ที่ยิงของที่ยังทำไม่ได้เข้าไปแล้วคาดว่าจะโดนปฏิเสธ พอทำได้แล้ว guard จะแดง
   นั่นคือสัญญาณให้มาอัปเดตไฟล์นี้ ไม่ใช่บั๊ก
3. **`unsupported` ว่างเมื่อไหร่** ถึงจะย้าย source of truth ไป backend ได้
   ก่อนหน้านั้น `lib/cbam/` คือตัวจริง (ดู `docs/API-CONTRACT.md`)
